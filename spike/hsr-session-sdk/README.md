# Session SDK spike

Экспериментальный встраиваемый Rust API из двух объектов. Основной SDK и приложение не изменены.

## Что работает

- `TrafficListener`: принимает расшифрованные команды, подтверждает UID только успешным token-ответом, различает сетевые потоки и эпохи подключения.
- Типизированные наблюдения `GetCurrentScene` и `GetInventory`, единое состояние для захвата и результатов запросов.
- `SessionRequester`: принимает согласованный `SessionTransport`, проверяет сессию и корреляцию, ограничивает ожидание, отклоняет поздние/чужие ответы.
- CLI для пассивного PktMon-захвата и воспроизведения исходных JSONL сниффера.
- Отчёт без UID, ключей, endpoint-адресов и значений игровых payload.

## Существенная незавершённая часть

**Транспорта отправки запросов в соединение официального клиента нет.** Пассивный `reliquary` не владеет игровым KCP-сокетом. Захваченные `conv` и ключ не позволяют библиотеке безопасно присвоить транспортную нумерацию клиента и сопоставить все параллельные ответы.

Встроенный requester на пассивном захвате возвращает `TransportUnavailable`. Для записей — `ReplayOnly`. Эти результаты не являются успешным сетевым запросом. Отправка проверена только тестовым транспортом из unit-тестов. Его ответы синтетические и не выдаются за ответы официального сервера.

`SessionTransport` — доверенный интерфейс для будущего кооперативного прокси/владельца соединения; одна реализация трейта сама по себе не доказывает владение реальным сокетом. Автоматической инъекции DLL, перехвата send-функций или внедрения UDP-пакетов в живую сессию прототип не выполняет.

## Живой захват

PktMon требует повышенных прав. Начать захват нужно **до входа в аккаунт**; уже открытый мир обычно требует возврата на экран входа и нового подключения. Игровые действия и перезапуск клиента выполняет пользователь.

```powershell
.\Start-Live.ps1 -Seconds 120
```

Скрипт при необходимости запрашивает UAC и запускает скрытый helper. Результат по умолчанию: `D:\HSR-Lab\protocol\4.6.0\session-sdk-live.json`. Проверять его нужно после окончания заданного интервала. Исторические ключи из JSONL не используются для отправки в сеть.

Текущее окружение при первой попытке: `StarRail.exe` не обнаружен, PktMon вернул отказ в доступе из неповышенного процесса. Отдельный отчёт: `session-sdk-live-attempt.json`. Это не успешная проверка живого захвата.

Ограничения прототипа: портовый фильтр не доказывает принадлежность пакетов PID игры; первый компонент PktMon выбирается как в существующем сниффере; одновременно сохраняется одна текущая подтверждённая сессия. Декодеры создаются отдельно для пар endpoint, но неизвестный сетевой трафик остаётся недоверенным. Обработка паники внешнего декодера сбрасывает соответствующий контекст.

## Пример встраивания

```rust,ignore
let listener = TrafficListener::new();
// Capture adapter calls listener.ingest_on_flow(flow_id, conv_id, &command).
let session = listener.active_session().ok_or(Error::NoSession)?;
let observed_scene = listener.read::<GetCurrentScene>(&session)?;

// A real, synchronized transport is a separate integration requirement.
let requester = SessionRequester::with_transport(listener, cooperative_transport);
let fresh_scene = requester.query(
    &session, GetCurrentScene, Duration::from_secs(3),
).await?;
```

Низкоуровневые ответы пока представлены типами protobuf текущей версии. Нормализованные предметные модели из проекта архитектуры в этот spike ещё не перенесены.
