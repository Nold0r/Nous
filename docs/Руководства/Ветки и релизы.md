# Ветки и релизы

Репозиторий: https://github.com/Nold0r/Nous

## Ветки

| Ветка | Для чего |
|---|---|
| `main` | Только готовый код. **Каждый push сюда собирает и публикует релиз**, и установленные копии Nous обновляются |
| `tab/overview` | Вкладка «Обзор» |
| `tab/characters` | Вкладка «Персонажи» |
| `tab/relics` | Вкладка «Реликвии» |
| `tab/map` | Вкладка «Карта» |
| `tab/settings` | Вкладка «Настройки» |
| `tab/design-system` | Dev-экран «Дизайн-система» |

Работа над вкладкой идёт в её ветке. Когда вкладка готова, ветка вливается в `main`:

```
git checkout main
git pull
git merge tab/map
git push            # запускает сборку релиза
```

Перед новой работой в ветке подтяните `main`, чтобы получить изменения оболочки: `git checkout tab/map && git merge main`.

> [!warning] Правки оболочки
> Общий код (`components/`, `ui/`, `lib/`, `src-tauri/`) лучше менять в `main` или в отдельной ветке и сразу вливать: если две вкладки поменяют его по-разному, будут конфликты.

## Автосборка

`.github/workflows/release.yml`, запускается на каждый push в `main`, кроме правок только в `docs/`, `app/scripts/dev/`, `.github/` и `*.md` (или кнопкой «Run workflow» в Actions):

1. Версия = `major.minor` из `app/src-tauri/tauri.conf.json` + номер запуска workflow (например `0.1.7`). Чтобы начать новую серию, поменяйте `0.1.0` на `0.2.0`.
2. Сборка установщиков NSIS и MSI, подпись пакетов обновления.
3. Релиз `v<версия>` с установщиками и `latest.json`.

Сборка идёт ~10–15 минут.

## Патчноуты

**Каждый релиз выходит с патчноутом.** Перед слиянием в `main` опишите изменения для пользователя в разделе `## Unreleased` файла `CHANGELOG.md` в корне репозитория: по-русски, простыми словами, риски отдельно (⚠️).

- Сборка берёт этот раздел как описание релиза на GitHub (и оно попадает в `latest.json` обновления).
- После публикации сборка сама переименует раздел в `## vX.Y.Z — дата` и откроет новый пустой `## Unreleased` (коммит `github-actions[bot]`). Поэтому перед следующей работой сделайте `git pull` в `main`.
- Если раздел пуст, в релиз попадут заголовки слияний с прошлого релиза и предупреждение в логе сборки — так делать не надо.

## Автообновление

Nous при запуске (только релизная сборка, не `tauri dev`) читает
`https://github.com/Nold0r/Nous/releases/latest/download/latest.json`. Если версия новее, внизу меню появляется «Доступна версия … — Обновить»: установщик скачивается, ставится в тихом режиме и перезапускает программу.

> [!danger] Ключ подписи
> Обновления подписаны ключом `~/.tauri/nous-updater.key` (секрет `TAURI_SIGNING_PRIVATE_KEY` в GitHub). Публичная половина — в `tauri.conf.json` (`plugins.updater.pubkey`). **Сохраните копию ключа.** Если он потеряется, установленные копии перестанут принимать обновления, и всем придётся переустановить Nous вручную.

## План доставки SDK и модулей

`codex/sdk` — отдельная экспериментальная ветка/worktree. В рамках этой работы нет push, слияния в `main` и выпуска. Ниже только порядок будущей доставки.

1. Перед слиянием сравнить ветку с актуальным `main`, перенести его новые исправления в экспериментальный worktree и разрешить конфликты в Cargo.lock, IPC, registry и CHANGELOG. Основную папку и ветки в ходе эксперимента не менять.
2. Проверить чистый checkout с recursive submodules: `cargo test --workspace --all-targets`, lint, TypeScript, тесты модулей и frontend build. CI теперь проверяет весь workspace, а не только Tauri lib; кэш Rust указывает на корень.
3. Собрать debug с отдельным identifier и проверить все модули off, возврат одной вкладки, прямой адрес отключённой вкладки, сохранение выбора после перезапуска. На копиях файлов проверить format 2 и миграцию с 1. Отдельно перед выпуском проверить живой вход, смену UID и запись после выхода.
4. Просмотреть `## Unreleased` в CHANGELOG: сохранить ещё не выпущенные пункты main и добавить описание SDK/модулей. Раздел станет общим патчноутом ближайшего релиза.
5. Только после отдельного решения о выпуске слить готовые изменения в `main` одним согласованным обновлением. Push запускает существующий release workflow, подпись и публикацию установщиков/latest.json. Не публиковать неполные промежуточные коммиты SDK.
6. Установленная версия найдёт обновление обычным механизмом. Сохранить identifier `com.nous.companion`, updater endpoint, публичный ключ и прежний ключ подписи. Профили Cargo и путь артефактов теперь корневые, Tauri CLI это разрешает через workspace.

Для обычного пользователя вкладки по умолчанию сохраняются. Переключатели модулей и каталог дизайн-системы доступны только в dev; release игнорирует старые dev-отключения. Настройки и обновление доступны при любом выборе модулей. Внешние разработчики могут получать те же данные из Rust SDK без запуска оболочки.

Файлы аккаунтов не меняют версию: format 2 и миграция 1 → 2 сохраняются, нового переноса пользовательских данных нет. Выбор и настройки модулей хранятся отдельным атомарным `modules.json` в папке данных приложения; WebView используется для браузерного запуска и первого переноса прежнего dev-выбора. Файлы аккаунтов при этом не меняются. Возврат на предыдущую версию, уже поддерживающую format 2, не требует обратной миграции. Возврат на старую версию с ошибочным чтением format 1 не использовать как восстановление; перед выпуском сохранить резервную копию аккаунтов.

Риски: смена путей workspace в автоматизации; ошибки границы protobuf → Command; незавершённые фоновые задачи стороннего встроенного модуля при выключении; Windows-зависимость PktMon; ошибка диска при последнем flush. Для снижения риска — тесты доменных команд, публичного API, ошибок/повторов записи, последовательности сервисов и ручная проверка debug. Живой перехват нельзя считать проверенным по одному smoke-тесту без игры. Существующая логика Veritas остаётся прежней, её установка не является частью проверки/доставки SDK.
