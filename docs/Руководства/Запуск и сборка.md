# Запуск и сборка

Команды npm выполняются в папке `app/`, команды Cargo workspace — из корня репозитория.

## Требования

- Node.js 24+, npm
- Rust **1.95+** (`rustup update stable`)
- Windows 10/11 с WebView2 (есть в системе)

## Команды

| Команда               | Что делает                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `npm install`         | Ставит зависимости                                                                                   |
| `npm run tauri dev`   | Приложение с горячей перезагрузкой. Правки интерфейса применяются сразу, правки Rust — с пересборкой |
| `npm run tauri:user` | То же, но «глазами пользователя»: dev-экраны (`devOnly`) скрыты, как в релизе. Без сборки установщика |
| `npm run dev`         | Только фронт в браузере на `localhost:5173`, без Rust. Профиль будет пустым                          |
| `npm run build`       | Проверка TypeScript и сборка фронта                                                                  |
| `npm run tauri build` | Установщик в `../target/release/bundle/`                                                      |
| `npm run test:data`   | Тесты разбора данных на записанных входах в игру, без запуска игры, см. [[Данные аккаунта#Проверки без входа в игру]] |
| `npm run assets`      | Скачать и нормализовать иконки и шрифт, см. [[Игровые ресурсы]]                                      |

## Частые проблемы

> [!bug] Звёзды или фон не обновились после правки
> Горячая перезагрузка не всегда перезапускает canvas. Нажмите **F5** в окне приложения.

> [!bug] `EBUSY: resource busy or locked … src-tauri\target`
> Vite не должен следить за `src-tauri`. Это уже отключено в `vite.config.ts` (`server.watch.ignored`).

> [!bug] `cfg_select` is unstable
> Старый Rust. Выполните `rustup update stable`.

> [!bug] Всплывающее окно обрезано или не видно
> Окно рендерится внутри акриловой панели, нужен портал, см. [[Фон и акрил#Ловушка с position: fixed]].

> [!bug] Приложение запустилось с пустым аккаунтом, в логе «account storage is unavailable»
> Папка `accounts` в данных приложения недоступна для чтения. Nous в этом случае работает без хранилища и ничего в ней не трогает; исправьте доступ к папке и перезапустите.

## Скорость сборки Rust

Замеры на машине разработки (Ryzen 5 3600, правка одной строки в `app/src-tauri/src/lib.rs` → готовый `nous.exe`):

| Где `target` и как собраны зависимости | Пересборка | Чистая сборка |
|---|---|---|
| Жёсткий диск, зависимости с отладочной информацией (так было) | 98 с | — |
| NVMe, зависимости с отладочной информацией | 41–43 с | 11 мин 50 с |
| NVMe, зависимости без неё | 23–24 с | 7 мин 22 с |
| То же и `crate-type = ["rlib"]` (так сейчас) | 12 с | не измерялась |

Что для этого сделано и что нужно повторить в новом worktree:

1. **`target` на быстром диске.** Репозиторий лежит на жёстком диске, а одна сборка пишет гигабайты. `target` в worktree — junction на SSD, для Cargo, Tauri и скриптов путь `target/…` остаётся прежним:

   ```powershell
   # из корня worktree; имя папки — имя worktree
   New-Item -ItemType Directory -Force C:\cargo-target\<worktree> | Out-Null
   cmd /c mklink /J target C:\cargo-target\<worktree>
   ```

   У каждого worktree свой каталог: `reliquary` — path-зависимость из submodule и собирается в каждом заново, а общий `target` перезаписывал бы чужой `nous.exe`.
2. **Зависимости без отладочной информации**: `[profile.dev.package."*"] debug = false` в корневом `Cargo.toml`. Свои крейты отлаживаются как раньше; отладчик не заходит внутрь зависимостей. Чтобы зайти в зависимость, временно закомментируйте эти две строки.
3. **`crate-type = ["rlib"]`** в `app/src-tauri/Cargo.toml`: варианты `staticlib` и `cdylib` из шаблона нужны только мобильным сборкам, а на Windows при каждой пересборке писали статическую библиотеку на 4 ГБ.

Не измерено, но может помочь: исключения Защитника Windows для `C:\cargo-target` и `%USERPROFILE%\.cargo`, линковщик `lld-link`.

## SDK и изолированная проверка

```powershell
# Из корня:
cargo test --workspace --all-targets
cargo run -p nous-hsr --example events -- --smoke
# Из app/:
npm ci
npm run lint
npx tsc -b
npm run test:modules
npm run build
npx tauri build --debug --no-bundle --config '{"identifier":"com.nous.devtest"}'
```

Debug exe: `target/debug/nous.exe`. Тестовый identifier хранит данные отдельно от `%APPDATA%\com.nous.companion`; не запускайте проверочную сборку с пользовательским identifier. Debug не требует администратора; захват без повышения сообщает `needs_admin`. При всех модулях off захват остановлен. Для разработки с изоляцией используйте тот же `--config` у `tauri dev`.

SDK не требует установленного Nous; подробнее [[SDK]]. Первая сборка reliquary с полным protobuf может занять значительное время и память.

## Автоматическая проверка интерфейса

`npm run test:modules` проверяет без React и браузера: фоновые модули и манифесты, синхронизацию состояния с Rust (`lib/live-core.ts`), слияние `world-changed` и округление характеристик реликвий. `npm run test:ui` проверяет реальные переключатели, меню, маршруты и localStorage через Playwright. Для браузерной проверки сначала запустите `npm run dev`, затем в другом терминале из `app/`:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/../target/playwright"
npx playwright install chromium
npm run test:ui
```

Браузеры и снимки (`target/ui-evidence/`) остаются в игнорируемом каталоге сборки. В CI обязательны тесты lifecycle, UI smoke можно запускать отдельно.

Для того же сценария внутри **изолированной debug-сборки** перед запуском exe задайте `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223`, затем `NOUS_CDP=http://localhost:9223` и `npm run test:ui`. Скрипт дополнительно проверяет `Versioned`-чтения IPC и остановку захвата при всех модулях off. Не задавайте remote debugging для обычного пользовательского запуска. После остановки и повторного запуска тестовой программы `NOUS_EXPECT_PERSISTED=true` включает проверку сохранённого all-off выбора до каких-либо переключений.

На этой машине WebView2 не применил CDP-порт из переменной окружения. Рабочая альтернатива: создать временную копию `app.windows` из `tauri.conf.json`, добавить в окно `additionalBrowserArgs: "--remote-debugging-port=9223"` (сохранив остальные штатные аргументы), задать тестовый identifier и передать файл через `--config`. Так проверена сборка из отчёта; тестовая конфигурация лежит в игнорируемом `target/`, в релиз она не входит. Метод подключения Playwright описан в [официальном руководстве WebView2](https://playwright.dev/docs/webview2).

`NOUS_RESTART_AFTER=true` запрашивает штатный перезапуск сразу после последнего сохранённого переключения; следующий запуск `test:ui` с `NOUS_EXPECT_PERSISTED=true` проверяет all-off выбор до каких-либо изменений. В Tauri он записывается в `modules.json`, поэтому не зависит от отложенной записи WebView localStorage.
