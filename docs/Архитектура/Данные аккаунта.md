# Данные аккаунта

Всё, что [[Сниффер]] узнаёт об аккаунте, хранится в **одном формате**: файл на аккаунт. Сделано по образцу [reliquary-archiver](https://github.com/IceDynamix/reliquary-archiver) (экспорт для оптимизатора Fribbels), но значения хранятся **сырыми**, как их шлёт игра: id предметов и броски характеристик, без названий и посчитанных чисел. Так формат не зависит от таблиц игры и не ломается при их обновлении; названия и значения подставляются при показе.

## Файлы

Папка данных приложения (`%APPDATA%\com.nous.companion\accounts\`):

| Файл | Что |
|---|---|
| `<uid>.json` | Аккаунт: профиль + инвентарь. Пишется атомарно (временный файл → переименование) |
| `current` | UID последнего аккаунта: его данные показываются при запуске как «с последнего входа» |
| `<uid>.relics.jsonl` | Журнал реликвий: сверка при каждом входе и каждое изменение. Нужен для проверки поведения id (см. ниже) |

Код: `src-tauri/src/account.rs` (хранение), `inventory.rs` (разбор пакетов), фронт: `src/lib/inventory.ts`.

## Формат `<uid>.json` (`format: 1`)

```json
{
  "format": 1,
  "uid": 700000000,
  "profile": { "nickname": "…", "level": 70, "stellarJade": 1234, … },
  "relics": { "17054": { "uid": 17054, "tid": 61011, "level": 15, "exp": 0,
               "mainAffixId": 1,
               "subAffixes": [{ "affixId": 4, "cnt": 3, "step": 2 }, …],
               "reforgeSubAffixes": [ … ],
               "equippedBy": 1310, "locked": true, "discarded": false,
               "firstSeen": 1793600000, "updatedAt": 1793600500 } },
  "lightCones": { "<uid>": { "tid", "level", "ascension", "superimposition", "equippedBy", "locked" } },
  "materials": { "<tid>": { "tid", "count", "expireTime?" } },
  "avatars": { "<baseAvatarId>": { "level", "exp", "ascension", "currentPath" } },
  "avatarPaths": { "<avatarId>": { "eidolon", "skillTree": { "<pointId>": level }, "lightCone", "relics": { "<slot>": relicUid } } },
  "syncedAt": 1793600000
}
```

- Значение доп. характеристики: `cnt × BaseValue + step × StepValue` из `RelicSubAffixConfig` (редкость = `MaxLevel / 3` из `RelicConfig`).
- `reforgeSubAffixes` — результат «Переменной кости», который игрок ещё не принял или не отклонил.
- `firstSeen`, `updatedAt` — время Nous, не игры. `firstSeen` переживает прокачку и переброс.
- При смене несовместимого формата число `format` растёт, старые файлы игнорируются (данные снова придут при входе).

## Откуда данные

| Пакет | Что |
|---|---|
| `GetBagScRsp` (вход) | Полные списки реликвий, конусов, материалов. Реликвии сверяются с сохранёнными → запись `login` в журнал |
| `GetAvatarDataScRsp` (вход) | Персонажи: `avatars` (уровень общий для всех путей) и `avatarPaths` (эйдолоны, следы, снаряжение каждого пути) |
| `PlayerSyncScNotify` | Изменения: `relic_list` / `del_relic_list`, `equipment_list` / `del_equipment_list`, `material_list`, `avatar_sync` |

## API

| Команда / событие | Что |
|---|---|
| `get_inventory` | Весь инвентарь текущего аккаунта |
| `get_relics` | Список реликвий |
| событие `inventory-changed` | `{ kind: "reset" }` — всё заменено (вход, другой аккаунт), перечитать; `{ kind: "changed", relics, deletedRelics, lightCones, materials, characters }` — изменения |
| `useInventory()` (`lib/inventory.ts`) | Хук: инвентарь, обновляется сам |

## Исследование: стабилен ли id реликвии

Нужно для будущих заметок к реликвиям: заметка привязывается к `uid` (`unique_id` игры).

| Вопрос | Ответ | Доказательство |
|---|---|---|
| Что такое `unique_id` | Счётчик аккаунта на сервере, растёт на 1 с каждым новым предметом | Дамп 02.11 02:08: 399 реликвий с id 254…17053; выпавшая в той же сессии получила **17054** = максимум + 1. Дыры в нумерации — разобранные реликвии |
| Используется ли id повторно | Нет признаков: новая реликвия получила следующий номер, а не свободный из дыр | Тот же дамп |
| Прокачка | Игра шлёт ту же реликвию с тем же `unique_id` и новым уровнем/бросками, без удаления | Так работает протокол (`relic_list` в `PlayerSyncScNotify` — обновление по id, удаление — только `del_relic_list`); reliquary-archiver и оптимизатор Fribbels обновляют реликвии по этому id |
| Переброс («Переменная кость», реликвия +15) | Результат сначала приходит в `reforge_sub_affix_list` той же реликвии; после выбора — в `sub_affix_list`, id тот же | Поля протокола; подтвердить в игре (ниже) |
| Повторный вход | Ожидается тот же id: это серверный счётчик | Подтвердить сверкой при входе (ниже) |

> [!todo] Проверка в игре
> С версией Nous, где есть этот журнал:
> 1. Войдите в игру (Nous сохранит реликвии).
> 2. Прокачайте любую реликвию на пару уровней.
> 3. Перебросьте реликвию +15 «Переменной костью»: и оставьте новый результат, и (на другой) старый.
> 4. Выйдите и войдите снова.
>
> Затем журнал `<uid>.relics.jsonl`: у записи `login` должно быть `reassigned: 0`, `gone` — только разобранные; у записей `relic` прокачанной и переброшенной реликвии — прежний `uid` и неизменный `firstSeen`.

> [!tip] Для заметок
> Ключ заметки — `uid`. Если игра когда-нибудь начнёт менять id, запасной ключ — «отпечаток» `tid + mainAffixId + affixId` доп. характеристик (при прокачке и перебросе меняются только `cnt`/`step`: «Переменная кость» перераспределяет улучшения между теми же характеристиками — тоже проверить по журналу). Сверка при входе (`reassigned`) сразу покажет такую поломку.

## Проверки без входа в игру

Nous **сам записывает фазу входа** каждой сессии (от `PlayerGetTokenScRsp` до списков инвентаря, ~1 с трафика) в `%APPDATA%\com.nous.companionecordings\<дата-время UTC>.jsonl`, хранит последние 20 (`src-tauri/src/recorder.rs`). Достаточно обычно зайти в игру с запущенным Nous.

```
npm run test:data        # в app/
```

прогоняет все записи через разбор (`src-tauri/src/replay.rs`) и проверяет:

- вход записан целиком: UID, сумка, персонажи;
- реликвии осмысленны: есть set/основная характеристика, уровень ≤ 15, ≤ 4 доп. характеристик;
- снаряжение согласовано: каждая надетая реликвия и конус есть в сумке, и реликвия указывает на того же персонажа;
- **id реликвий между входами**: каждый вход сравнивается с предыдущим того же аккаунта; `reassigned > 0` (id стал означать другую реликвию) — ошибка.

Папку можно подменить: `NOUS_RECORDINGS=<папка>` (подходят и дампы `spike/hsr-sniff`). Без записей тест проходит с пометкой «нет записей» — так он работает в CI. Записи содержат данные аккаунта и в репозиторий не кладутся.

`cargo test --lib` — плюс синтетические тесты: вход, повторный вход, прокачка, переброс, удаление, сохранение, запись входа.

> [!note] Наблюдение
> У 181 из 400 реликвий в дампе непустой `preview_sub_affix_list`. Что именно это за предпросмотр, пока не выяснено; поле хранится как есть.
