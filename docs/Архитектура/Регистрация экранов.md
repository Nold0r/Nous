# Регистрация экранов

Экран (фича) регистрируется **автоматически**: достаточно создать папку `src/features/<id>/` с файлом `index.ts`, который по умолчанию экспортирует описание через `defineFeature`. Ни меню, ни маршруты трогать не нужно.

## Как это работает

1. `registry.ts` через `import.meta.glob('./*/index.ts')` находит все папки фич.
2. Отбрасывает фичи с `devOnly: true` в релизной сборке. Dev-запуск — это `npm run tauri dev`, `npm run dev` или `npm run tauri build --debug` (флаг `isDevLaunch` в `registry.ts`: `import.meta.env.DEV` или `TAURI_ENV_DEBUG`). `npm run tauri:user` выключает флаг, чтобы посмотреть приложение как пользователь.
3. Проверяет то, что не может проверить TypeScript: формат `id`, дубликаты, несколько `isDefault`. Ошибки пишет в консоль.
4. `Sidebar` группирует фичи по категориям (см. [[Категории меню]]) и рисует пункты.
5. `App.tsx` создаёт маршрут `/#/<id>/*` для каждой фичи. Звёздочка значит, что внутри фичи можно делать свои подстраницы.

## FeatureDef — все поля

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `id` | `string` | да | Уникальный, kebab-case. Он же адрес: `/#/my-feature` |
| `title` | `string` | да | Название в меню |
| `icon` | `IconSource` | да | Имя игровой иконки (`'map'`, `'characters'`…) или компонент `lucide-react`, см. [[Иконки]] |
| `category` | `CategoryId` | да | Раздел меню. Опечатка — ошибка компиляции |
| `component` | `ComponentType` | да | Компонент экрана |
| `order` | `number` | нет | Порядок внутри раздела, меньше — выше. По умолчанию 0 |
| `isDefault` | `boolean` | нет | Открывается при запуске. Только у одной фичи |
| `badge` | `string` | нет | Метка рядом с названием (`beta`, `dev`) |
| `devOnly` | `boolean` | нет | Только в dev-запуске (`tauri dev`, `tauri build --debug`), в релизе скрыт |

## Минимальный пример

```ts
// src/features/warps/index.ts
import { defineFeature } from '../types'
import { WarpsPage } from './WarpsPage'

export default defineFeature({
  id: 'warps',
  title: 'Прыжки',
  icon: 'inventory',
  category: 'inventory',
  order: 2,
  component: WarpsPage,
})
```

```tsx
// src/features/warps/WarpsPage.tsx
import { EmptyState, Page } from '../../ui'

export function WarpsPage() {
  return (
    <Page title="Прыжки" subtitle="История круток">
      <EmptyState icon="inventory" title="История пуста" />
    </Page>
  )
}
```

## Подстраницы внутри фичи

Фича смонтирована на `/<id>/*`, поэтому внутри можно объявить свои маршруты:

```tsx
import { Route, Routes } from 'react-router-dom'

export function RelicsPage() {
  return (
    <Routes>
      <Route index element={<RelicList />} />
      <Route path=":relicId" element={<RelicDetails />} />
    </Routes>
  )
}
```

Пункт меню остаётся подсвеченным на всех подстраницах.

## Структура папки фичи

```
features/warps/
├─ index.ts          описание (defineFeature) — единственная точка входа
├─ WarpsPage.tsx     корневой компонент экрана
├─ components/       компоненты, нужные только этой фиче
├─ api.ts            вызовы invoke() в Rust, если фича ходит в бэкенд
└─ types.ts          типы данных фичи
```

> [!tip] Где чему место
> Компонент нужен двум фичам → в [[Компоненты|дизайн-систему]]. Логика нужна двум фичам → в `src/lib/`. Фичи друг друга не импортируют, см. [[Обзор архитектуры#Правила зависимостей]].
