# Регистрация экранов

Реестр обнаруживает встроенные `ModuleDef` из `app/src/features/*/index.ts`. Модуль — id, название, необходимые сервисы, настройки, необязательная фоновая работа и ноль или больше экранов `ScreenDef`. Динамические библиотеки не загружаются. `settings/index.ts` отдельно регистрирует обязательный экран оболочки и исключён из списка отключаемых модулей.

## Контракты

`ModuleDef`: `id`, `title`, `requires?: ServiceId[]`, `screens?: ScreenDef[]`, `devOnly?`, `settings?: { defaults }`, `start?: (ModuleContext) => (() => void) | void`.

`ModuleContext`: `signal: AbortSignal`, `services` (HSR только при `requires: ['hsr']`), `settings` (defaults + сохранённые значения), `storage.get/set` в пространстве модуля, `navigate(screenId)`.

`ScreenDef`: `id`, `title`, `icon`, `category`, `component`; необязательно `order`, `isDefault`, `badge`, `devOnly`. Адрес `/#/<screen-id>/*` не зависит от id модуля. Один модуль может иметь несколько экранов или только фоновую работу.

```ts
import { defineModule } from '../types'
import { WarpsPage } from './WarpsPage'

export default defineModule({
  id: 'warps',
  title: 'Прыжки',
  requires: ['hsr'],
  settings: { defaults: { notifications: false } },
  screens: [{ id: 'warps', title: 'Прыжки', icon: 'inventory',
    category: 'inventory', component: WarpsPage }],
  start({ signal, storage }) {
    // Subscribe independently of the active route; clean up on disable.
    const timer = setInterval(() => {
      if (!signal.aborted) storage.set('last-check', Date.now())
    }, 60_000)
    return () => clearInterval(timer)
  },
})
```

Текущие модули: «Обзор», «Карта», «Персонажи», «Реликвии», dev-only «Дизайн-система». Первые четыре требуют HSR. Дополнительных фоновых задач у их существующих экранов-заглушек нет.

## Выключение в dev

В «Настройках → Модули» есть переключатель на каждый доступный модуль. Раздел показывается только при `isDevLaunch`: Vite DEV или `TAURI_ENV_DEBUG === 'true'`, кроме `VITE_USER_MODE === 'true'`. `npm run tauri:user` и release используют встроенные значения; сохранённые dev-отключения на них не влияют.

В Tauri выбор и настройки сохраняются отдельным файлом `<app data>/modules.json` (`disabled`, `settings`): IPC подтверждает атомарную запись до изменения переключателя. При запуске конфигурация загружается до включения сервисов и маршрутов. Это обеспечивает сохранение даже при немедленном перезапуске, когда WebView ещё не успел сбросить localStorage на диск. Первый запуск переносит прежний `nous.modules.v1` из WebView, если файл ещё не создан. В обычном браузере используется localStorage. Произвольное пространство данных модуля остаётся `nous.module.<id>.v1.<key>`. Файлы аккаунтов не меняются; тестовый identifier использует отдельную папку. Новый неизвестный ранее модуль включён по умолчанию. Ошибка сохранения видна в настройках; текущий выбор при ней не меняется.

Отключение убирает все экраны модуля из одного списка, которым пользуются и Sidebar, и Router. Пустые категории исчезают. Старый адрес отключённой вкладки переадресует на активную вкладку по умолчанию либо в настройки. При всех модулях off остаются настройки, профиль и элементы оболочки, а захват остановлен.

## Lifecycle и сервисы

`ModuleRuntime` запускает `start` один раз на включение, после подключения нужных сервисов. Смена маршрута модуль не перезапускает. Отключение сразу вызывает abort и функцию остановки; модуль обязан отменять свои таймеры, подписки и незавершённую работу. Изменение сохранённых настроек перезапускает его lifecycle. Асинхронные переходы сервисов упорядочены, устаревший запуск после отключения не запускает фоновую задачу.

HSR общий: первый потребитель включает захват через `set_capture_enabled`, последний отключает. Независимый модуль без `requires` работает без HSR. Ошибка lifecycle одного модуля не обрушает оболочку; она видна в настройках. Экраны дополнительно обёрнуты в `ErrorBoundary`.
