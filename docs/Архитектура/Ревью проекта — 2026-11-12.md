# Ревью проекта — 2026-11-12

Ревью кода `origin/main` v0.1.13 с тремя коммитами карты (`tab/characters`): тесты модулей и их взаимодействия, сверка с [[Целевая архитектура|целевой архитектурой]], поиск багов, скорость сборки и запуска. Большая часть найденного исправлена в ветке `fix/review-2026-11-12`; что осталось, перечислено в разделе «Не исправлено».

Продолжает [[Ревью архитектуры — 2026-11-03]] и аудит Codex `audit/2026-11-03/` (находки S01–S28).

## Не исправлено

| Что | Почему |
|---|---|
| `protobuf` закреплён на 3.7.1 с RUSTSEC-2024-0437 (S01) | Версию закрепляет `vendor/reliquary`: его сгенерированный код проверяет `VERSION_3_7_1`. Нужен форк reliquary с перегенерацией или обновление upstream. Уязвимость — переполнение стека при разборе, `catch_unwind` от него не защищает |
| Привязка изменений к подтверждённой игровой сессии (S04) | Требует решения, что считать подтверждённой сессией; это изменение модели, а не правка |
| Неограниченные очереди подписчиков и reliquary (S11) | Нужен контракт «отстал — перечитай» для подписчиков SDK |
| Выбор сетевого адаптера при смене VPN (S13) | Исправлено частично ещё до ревью; нужна живая проверка с VPN |
| Дубли в журнале реликвий при частичном сбое записи (S09), сверка `live`-прыжков с официальной историей (S24), пропуски в истории при остановке на известной записи (S23, часть) | Не дошли руки; на данные аккаунта не влияют |
| Транзакционность установки DLL Veritas (S07, S08, S27), гонки настроек оверлея (S20), проверки значений Veritas (S25) | Модуль Veritas заслуживает отдельного прохода с игрой |
| Гонки чтения статусов `get_game_status` и подобных (S18) | Не перепроверялись в текущем коде |
| 38 МБ карт (`app/public/maps`, 345 файлов) встраиваются в exe | Вынос в ресурсы установщика меняет раздачу файлов оверлею и dev-серверу; нужна проверка в собранном приложении |
| Записи входа и снимки (почта, друзья) лежат открытым текстом; `csp: null` | Требуют решения владельца проекта |
| Автоперезапуск захвата после ошибки | Сейчас ошибка видна в статусе; перезапуск — по кнопке или при следующем запуске |

## Сборка и запуск

Репозиторий и все каталоги `target` (222 ГБ на четыре worktree) лежали на жёстком диске 7200 об/мин. Замеры цикла «правка одной строки Rust — готовый exe» на Ryzen 5 3600:

| Конфигурация | Пересборка | Чистая сборка | `nous.pdb` |
|---|---|---|---|
| Было: `target` на жёстком диске | 98 с | — | 779 МБ |
| `target` на NVMe | 41–43 с | 11 мин 50 с | 780 МБ |
| NVMe и зависимости без отладочной информации | 23–24 с | 7 мин 22 с | 118 МБ |

В чистой сборке 9 минут из 12 занимал один крейт `reliquary` (сгенерированный protobuf-код); без отладочной информации — 5,4 минуты.

Сделано:

- `target` в рабочих папках `Nous` и `Nous-inventory` — junction на `C:\cargo-target\<папка>`; как повторить в новом worktree, описано в [[Запуск и сборка]].
- `[profile.dev.package."*"] debug = false` в корневом `Cargo.toml`.
- `crate-type = ["rlib"]`: каждая пересборка больше не пишет статическую библиотеку на 4,2 ГБ.
- Удалены старые каталоги сборки на 106 ГБ.
- CI: тесты Rust идут в профиле release и делят зависимости со сборкой релиза. Локально этот вариант не проверялся — первый прогон в CI покажет.

Запуск приложения:

- Стартовый JS-файл уменьшился с 1 241 КБ до 354 КБ (gzip 389 → 114 КБ): экраны «Персонажи», «Инвентарь», «Карта» и каталог дизайн-системы загружаются при первом открытии. Окна оверлея Veritas теперь тоже не тянут их за собой.
- Карта в режиме слежения двигает все метки одним `transform`, а не пересчитывает позицию каждой метки каждый кадр.
- Чтение аккаунта при старте занимает 50 мс и узким местом не было.
