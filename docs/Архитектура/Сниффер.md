# Сниффер

Системный модуль, общий для всех экранов с данными из игры. Он пассивно читает трафик игры и восстанавливает из него состояние: профиль, текущую локацию, позицию игрока, открытые сундуки.

> [!info] Безопасность
> Сниффер только **читает копию** сетевого трафика через встроенный в Windows PktMon. В процесс игры он не лезет, пакеты не отправляет и не меняет. Риск и ограничения: [[Источники данных]].

## Файлы (`app/src-tauri/src/`)

| Файл | Что делает |
|---|---|
| `sniffer.rs` | Захват PktMon в фоне, расшифровка через reliquary, статус, события во фронт |
| `game.rs` | `GameState`: разбирает команды игры, хранит профиль и карту, сохраняет на диск |
| `profile.rs` | `PlayerProfile` и команда `get_profile` |
| `map.rs` | `MapState`, `Position`, команды `get_map_state`, `get_opened_chests` |

Reliquary подключён из локальной копии `vendor/reliquary` (тег v24.0.0 = игра 4.6). После крупных патчей игры его нужно обновлять.

## Условия работы

1. **Права администратора.** Без них статус `needs_admin`. В релизе на экране «Карта» есть кнопка «Перезапустить от администратора». В dev-режиме запустите терминал от администратора и потом `npm run tauri dev`.
2. **Nous запущен до входа в игру.** Ключ сессии виден только при логине. Если игра уже запущена, выйдите на экран «Нажмите, чтобы начать» и войдите снова.
3. VPN (WireGuard и т. п.) поддерживается: пакеты без Ethernet-заголовка оборачиваются.

## Статусы (`sniffer-status`)

| `state` | Значит |
|---|---|
| `starting` | Запуск захвата |
| `needs_admin` | Нет прав администратора |
| `waiting_for_login` | Захват идёт, входа в игру ещё не было |
| `connected` | Вход пойман, данные расшифровываются |
| `error` | Захват остановился, текст в `message` |

## Команды игры, которые разбираются

| Команда | Что берём |
|---|---|
| `PlayerGetTokenScRsp` | UID. Если UID сменился, профиль другого аккаунта сбрасывается |
| `PlayerLoginScRsp.basic_info`, `PlayerSyncScNotify.basic_info` | Ник, уровень, энергия освоения, звёздный нефрит, кредиты |
| `StaminaInfoScNotify` | Энергия освоения и резервная энергия |
| `GetPlayerBoardDataScRsp` | `current_head_icon_id` — аватар |
| `EnterSceneByServerScNotify`, `GetCurSceneInfoScRsp` | План, этаж, вход, id ведущего персонажа и его позиция |
| `SceneEntityMoveCsReq` | Позиция игрока при движении (не чаще 10 раз в секунду во фронт) |
| `GetSceneMapInfoScRsp` | Открытые сундуки этажа (поле `lighten_section_list`, см. [[Протокол — карта и сундуки]]) |
| `OpenChestScNotify` | Только что открытый сундук + где стоял игрок (`opened_chest_positions.json`) |
| `SceneInfo.entity_list` / `entity_group_list`, `SceneGroupRefreshScNotify`, `InteractPropScRsp`, `maze_prop_list` | Состояние (`PropState`) каждого объекта этажа (`prop_states.json`): 8 якорь активирован, 12/13 сундук закрыт/открыт, 20 скрыт… |
| `SceneEntityMoveCsReq.map_layer` | Слой карты (часто 0, поэтому карта определяет слой по высоте) |

## События во фронт

| Событие | Данные | Слушает |
|---|---|---|
| `profile-changed` | `PlayerProfile` | `useProfile()` в `lib/profile.ts` |
| `map-changed` | `MapState` | `useMapState()` в `lib/map.ts` |
| `player-moved` | `Position` | `useMapState()` |
| `sniffer-status` | `SnifferStatus` | `useSnifferStatus()` в `lib/sniffer.ts` |

## Что сохраняется на диск

В папке данных приложения (`%APPDATA%\com.nous.companion\`):

- `profile.json` — последний профиль. При следующем запуске он показывается как `cached` («Данные с последнего входа»), пока игра не подключится.
- `opened_chests.json` — открытые сундуки по этажам, чтобы прогресс был виден и без игры.
