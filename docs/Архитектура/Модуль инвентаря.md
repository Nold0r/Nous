# Модуль инвентаря

Модуль `inventory` (`app/modules/inventory/`, адрес `/#/inventory`, см. [[Модули]]). Раньше назывался «Реликвии» (`relics`). Три вкладки, выбранная запоминается:

| Вкладка | Что показывает |
|---|---|
| Реликвии | Карточки (`ItemCard`): набор, слот, уровень, характеристики иконками (`StatLine`, ◆ — улучшения), кто носит, замок, отметка «на разбор», заметка. Фильтры `FilterMenu` с белым и чёрным списком: слот, набор, основная, доп. характеристики (нужны все включённые, ни одной исключённой), состояние (заблокирована, на разбор, надета, с заметкой); теги выбранного (`FilterTags`); поиск по заметкам и наборам; сортировка |
| Световые конусы | Название, уровень, наложение, кто носит, замок; фильтр по редкости |
| Материалы | Группы: «Улучшение реликвий» (опыт реликвий, обломки, смолы, Кость вероятностей, Ключ вмешательства), «Развитие персонажей и конусов», «Прочее» |

Данные — `useInventory()` (см. [[Данные аккаунта]]), обновляются сами во время игры.

## Новые реликвии

- **Подгружаются сами.** Выпавшая реликвия приходит в `PlayerSyncScNotify` и сразу появляется на экране (событие `inventory-changed`), без перезахода. Реликвии, выбитые без Nous, появятся при следующем входе.
- **Пометка «Новая»** держится 24 часа (`NEW_RELIC_SECONDS` в `lib/inventory.ts`) от момента, когда Nous впервые увидел реликвию (`firstSeen`): золотая метка и подсветка карточки, счётчик «N новых» в панели (клик — показать только их), пункт «Новая (за сутки)» в фильтре «Состояние», сортировка «Сначала новые».
- **Первый импорт — не новые.** `inventory.importedAt` — время первого полного списка аккаунта: всё, что было тогда, у игрока уже было. В файлах до этого поля его нет, их реликвии считаются старыми.

## Заметки к реликвиям

Клик по карточке открывает широкое окно (`Modal size="lg"`): слева реликвия и характеристики с названиями, справа бонусы набора и заметка (`TextArea`, Ctrl+Enter — сохранить). Пустая заметка удаляется.

- Хранятся в файле аккаунта, поле `notes.relics`: `{ "<uid реликвии>": { "text", "updatedAt" } }` — у каждого аккаунта свои.
- Ключ — `uid` реликвии: он не меняется при прокачке, перебросе и надевании (см. [[Данные аккаунта#Исследование: стабилен ли id реликвии]]).
- Заметка разобранной реликвии не удаляется, просто не показывается.
- Не длиннее 2000 символов, пробелы по краям обрезаются.

| Команда / событие | Что |
|---|---|
| `get_notes` | Заметки текущего аккаунта |
| `set_relic_note(uid, text)` | Записать заметку; пустой текст удаляет. Ошибка, если аккаунт ещё не определён |
| событие `notes-changed` | Новые заметки целиком |
| `useNotes()`, `setRelicNote()` (`lib/inventory.ts`) | Хук и запись с фронта |

Код: `crates/nous-core/src/notes.rs` (модель), `Client::set_relic_note` (запись и событие), команды в `app/src-tauri/src/ipc.rs`.

> [!warning] Старые версии
> Nous до этой версии не знает поля `notes` и при сохранении аккаунта выбросит его. Не запускайте старую сборку на том же профиле, если заметки важны.

## Таблицы игры

Названия и значения берутся из таблиц StarRailRes (русские, `index_new/ru`). `npm run game-data` (`scripts/fetch-game-data.mjs`) скачивает их и оставляет только нужные поля в `src/assets/data/game-data.json` (~600 КБ). Файл грузится отдельным чанком при первом открытии экрана (`lib/game-tables.ts`, `useGameTables()`). Картинки реликвий, конусов и материалов грузятся с StarRailRes по путям из таблиц.

После обновления игры: `npm run game-data` и закоммитить файл. Реликвия, которой нет в таблицах (новый набор), не показывается до обновления таблиц.

Значения характеристик:

- основная: `base + step × уровень` (`relic_main_affixes`);
- дополнительная: `cnt × base + step × step` (`relic_sub_affixes`), как в [[Данные аккаунта]];
- проценты — с одним знаком, скорость — с одним знаком, остальное — целым (округление вниз).

Имя Первопроходца берётся из ника профиля.

## Проверка

`cargo test -p nous-core` — запись, обрезка и удаление заметок, сохранение с аккаунтом, событие `notes-changed`, первый импорт не «новый», новая реликвия сразу уходит в интерфейс.

Вживую: `npm run tauri dev` от администратора, вход в игру скриптом (см. [[Вход в игру скриптом]]), затем открыть «Инвентарь».
