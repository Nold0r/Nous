# SDK и модули — отчёт

Дата: 2026-11-03. Рабочая папка: `D:\Documents\ClodeCode\Nous-sdk`, ветка `codex/sdk`. Экспериментальная версия: push, слияние в main и выпуск не выполнялись. Основная рабочая папка `Nous` использовалась только для чтения указанного архитектурного ревью; изменения кода и документов делались в этом worktree.

## Что сделано

Выделен независимый Rust SDK, а приложение стало его Tauri-адаптером. Введён отдельный контракт встроенного модуля с необязательными экранами и фоновым lifecycle. Пять существующих вкладок зарегистрированы как модули; настройки остались обязательной частью оболочки.

Ранее исправленные гарантии сохранены: `Versioned { revision, data }`, `account-changed`, прежние команды и имена событий, отложенное сохранение, формат аккаунта 2 и миграция с 1, ErrorBoundary. Захват остаётся пассивным: только копия трафика через PktMon, без доступа к процессу/памяти игры и отправки игровых пакетов. Логика согласия, установки и работы существующей опции Veritas не менялась; её единственное изменение в исходнике — новый путь к функции времени из ядра.

## Структура и API

| Часть | Назначение |
|---|---|
| Корневые `Cargo.toml`, `Cargo.lock` | Workspace из трёх крейтов, единые зависимости и прежние профили overflow-checks |
| `crates/nous-core` | Профиль, инвентарь, мир, бои, прыжки, снимки; предметный Command, GameState, ревизии, события и Client; AccountStore и FileStore |
| `crates/nous-hsr` | PktMon и reliquary, protobuf → обычные предметные команды, запись/replay входа, официальный импорт прыжков, Sdk |
| `app/src-tauri/src/ipc.rs`, `lib.rs` | Прежние IPC-чтения через SDK, мост событий, управление общим HSR-сервисом |
| `app/src-tauri/src/module_config.rs` | Отдельный атомарный файл настроек платформы `modules.json` |
| `app/src/features/types.ts`, `registry.ts`, `module-runtime.ts`, `ModuleProvider.tsx` | ModuleDef/ScreenDef, активные экраны, lifecycle и зависимости модулей |
| `examples/events.rs` | Консольный потребитель без Tauri |

`nous-core` не зависит от Tauri, AppHandle, reliquary, protobuf и PktMon. `nous-hsr` не зависит от Tauri. Это дополнительно проверено деревьями зависимостей (`cargo tree -p nous-core`, `cargo tree -p nous-hsr`).

Публичный вход: `Sdk::new(data_dir)` либо `Sdk::with_store(Arc<dyn AccountStore>, recordings_dir)`. Доступны `start_capture`, `stop_capture`, `status`, `read`, `subscribe`, `client`. `read` возвращает согласованный `Versioned<Account>`, а Client также позволяет читать проекции, обрабатывать предметные команды и выполнять явный flush. Подписка — независимый mpsc receiver событий `{ name, payload }`, пригодных для IPC и консоли. Ошибки возвращаются через Result, фоновые ошибки доступны как `sdk-error`; статусы захвата сохраняют `sniffer-status`, добавлен `stopped`.

`AccountStore` подменяется памятью в тестах. FileStore сохраняет прежнюю раскладку `accounts/`, формат 2, миграцию 1 → 2 и исходник нечитаемого файла. Невозможность сохранить исходник возвращает ошибку и запрещает его замену. Запись снимка и журнала вынесена с пути обычных пакетов; чтения и новые команды продолжаются во время записи. Ошибка сохранения оставляет данные для повтора и запрещает переключить UID до успешного сохранения прошлого аккаунта. Подробный контракт и пример подключения — [[SDK]]. Тестовое приложение и оба dev-сервера после проверок остановлены.

## Модули и настройки

`ModuleDef` описывает id, название, `requires`, необязательные `screens`, настройки и `start(context)`, возвращающий остановку. Context даёт AbortSignal, объявленные сервисы, пространство хранения, настройки и навигацию. Модуль без экранов поддерживается и проверяется тестом. Маршрут не управляет фоновым lifecycle.

В dev: «Настройки → Модули» → выключить «Обзор», «Карта», «Персонажи», «Реликвии», «Дизайн-система». Отключение одновременно удаляет меню и маршрут, вызывает abort/stop; пустые категории скрываются. Первый потребитель HSR включает захват, последний выключает. При всех off остаются настройки и оболочка, прямые адреса отключённых экранов переадресуют в настройки. Можно сразу вернуть одну вкладку.

Раздел определяется существующим `isDevLaunch`: DEV или TAURI_ENV_DEBUG, кроме VITE_USER_MODE. В пользовательском режиме/release переключателей нет, dev-отключения игнорируются, четыре пользовательские вкладки включены, дизайн-система скрыта.

В Tauri выбор и настройки атомарно записываются в `<app data>/modules.json` до подтверждения изменения UI. Загрузка завершается до запуска модулей. Первый запуск переносит прежний dev-выбор из WebView, если файла ещё нет. В браузере сохраняется localStorage. Данные модулей не добавляются в файлы аккаунтов. Подробности — [[Регистрация экранов]].

## Ограничения

Живой пассивный захват из нового SDK с правами администратора и полноценный вход/бой в этой сборке не выполнялись. Без повышения получен ожидаемый NeedsAdmin; обработка данных проверена синтетикой и реальными записями. UAC и установщик release в этой работе не запускались. Veritas не устанавливался, его внешние интеграционные проверки не выполнялись.

SDK захвата предназначен для Windows; само ядро от Windows не зависит. Один каталог файлов обслуживает один экземпляр SDK: межпроцессной блокировки нет. Подписчик должен читать или уничтожать receiver, чтобы очередь не росла. При ошибке диагностический журнал может повторить строки при следующем сохранении; состояние аккаунта повторно сохраняется целиком. Существующие экраны-заглушки не получили новой предметной функциональности — сделана их модульная граница.

## План доставки обычным обновлением

Выпуск не сделан. Подробный порядок добавлен в [[Ветки и релизы]]:

1. Перед отдельным решением о выпуске сверить экспериментальную ветку с актуальным main и перенести его новые изменения в этот worktree; разрешить конфликты workspace/IPC/registry/CHANGELOG.
2. Повторить проверки на чистом checkout с submodules и debug с отдельным identifier. Перед публичным релизом проверить живой вход, смену UID и сохранение при выходе на копиях данных.
3. Проверить русское `## Unreleased`: новые пункты SDK/модулей добавлены, прежние невыпущенные изменения сохранены.
4. Только затем согласованно слить готовую ветку в main. Один push запустит существующий workflow, подпишет обновление прежним ключом и опубликует установщики/latest.json. В этой работе этого не происходило.
5. Сохранить production identifier, updater endpoint и ключ подписи. Пользователь получит обычное уведомление Nous; переустановка и ручной перенос аккаунтов не нужны.

Аккаунты совместимы с прежним format 2, миграция с 1 сохранена. Новый modules.json независим от аккаунтов; release игнорирует dev-отключения. Возврат на предыдущую версию, поддерживающую format 2, не требует обратной миграции. Основные риски доставки — пути артефактов Cargo workspace, граница декодирования и корректная остановка будущих фоновых модулей; CI расширен на весь workspace и тесты lifecycle.
